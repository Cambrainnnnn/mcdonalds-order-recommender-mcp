# Hermes 技能行为验收

先在新聊天显式调用 `/meal-recommendation` 加下列需求，再开新聊天仅发送自然语言，分别检查“加载后行为”和“自动发现技能”。保存工具记录和最终回答；仅凭Agent说自己使用了技能不能证明调用正确。使用本次线上目录，不设虚构固定价。

| 场景 | 输入/操作 | 核对证据 |
| --- | --- | --- |
| 类别+口味+禁选 | 两份汉堡，最好麦辣鸡腿堡，需要一些小食，不要麦乐鸡块 | 查询真实目录；只澄清未确认的小食数量/范围；确认后最多3个有意义场景；每次至少2个汉堡、有小食且exclude包含麦乐鸡块所有规格 |
| 强制具体餐品 | 必须两个麦辣鸡腿汉堡、小食一份 | 不擅自用其他汉堡替换，不机械跑类别放宽 |
| 规格歧义 | 我要可乐两杯 | 存在多规格时澄清；未确认前不默认大杯 |
| 明确允许替代 | 可乐小杯大杯都可以，两杯 | 仅接受已确认且存在的规格；集合数量至少2，不把模糊查询自动当授权 |
| 单位 | 鸡翅4块、汉堡1个 | 若鸡翅规格2块，quantity=2；工具结果与最终块数一致 |
| 修改数量 | 先汉堡1个、鸡翅2块、预算50元；再汉堡改成2个，其余不变 | 完整更新保留鸡翅和5000分预算，汉堡不是3个 |
| 清除条件 | 先预算30元、最好冰淇淋；再取消预算和冰淇淋偏好 | 新需求中原条件不残留，旧结果不冒充新结果 |
| 硬约束冲突 | 必须鸡翅，又不要任何鸡翅 | 先澄清，不自行删约束 |
| 无候选 | 正价必选、预算0元且不接受替代 | 若无合法零价供给，说明当前需求无推荐，不提高预算或反复建会话；不声称缺货 |
| 部分场景失败 | 测试环境某场景返回内部错误，其他场景正常 | 不将错误当无解；最多一次有依据重试，最终说明比较不完整 |
| 结果重复 | 多场景返回同一实际组合 | 合并展示，不凑三方案；差价用真实总额计算 |
| 全局最优请求 | 允许买多个套餐，找全平台最低 | 披露搜索及维护数据范围，不宣称已穷举全平台 |

若场景所需线上商品/套餐不存在，记录前置条件不足，不算成功。核对“最低价”是否准确，需要独立目录全集与求解结果，技能验收本身不能替代算法验收。离线错误注入应在测试环境进行，不影响生产服务。
